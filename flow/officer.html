02 / What they can do

Own the week.
Respect the lock.

This is the role that touches the most data. Every write, import, override and export leaves an audit receipt. The design goal is speed on the parade ground without quietly widening access.

01

Run the wing register

Read and edit every active cadet, filter by department, year, platoon or certificate, and add a record with mandatory DPDP consent.

Live MVP
02

Enrol a whole batch

Download the Excel template, import up to 5 MB in one request, and upsert by register number so re-uploads do not duplicate cadets.

Live MVP
03

Mark any parade

Open a wing or platoon session, mark exceptions, mark everyone present, and survive a weak network with the offline queue.

Live MVP
04

Correct a locked parade

After the 24-hour lock, only an officer can amend. The same save call is recorded as an override with actor, role and IP.

Live MVP
05

Export for Group HQ

Choose columns and download Excel, CSV or PDF. Sensitive contact columns stay officer-only and every download is audited.

Live MVP
06

Publish unit news

Notices are live. The news and events write endpoints exist, but there is no officer composer screen for them yet.

Api-ready UI

Can authority

  • See the whole wing and all contact PII, including parent contact.
  • Create and edit cadets; bulk-upload a batch; download the template.
  • Open wing-wide or platoon parades and mark any active cadet on that roster.
  • Amend a session after the 24-hour lock, with an audit override.
  • Export Excel, CSV or PDF including phone, email and parent contact.
  • Publish, edit and soft-withdraw announcements.
  • Create staff accounts, but never a super admin.

Cannot guardrails

  • Deactivate or delete a cadet — soft deactivation is SUPER_ADMIN only.
  • Mint another SUPER_ADMIN account.
  • Reset a password or deactivate a user login — no endpoint exists.
  • Read the audit trail in the UI — writes only, no read API yet.
  • Export a column outside the whitelist, or exceed the row cap silently.
  • Target a notice to one platoon — the schema has no audience field.
  • Mark attendance without the server resolving your wing scope.

04 / Evidence & gaps

Built into the API.
Polished in the UI.

The officer workflow is the most complete part of the MVP. The gaps are mainly write surfaces that exist as endpoints but not as screens, plus the missing audit reader.

Scope

Wing authority

Officers resolve to an unrestricted staff scope. Leaders resolve from their linked cadet record.

common/scope.tsstaffScope()

Register

Create & edit

Officer-only writes, mandatory consent, and a single upsert path shared by manual entry and bulk upload.

POST /cadetsPATCH /cadets/:id

Bulk

Batch enrolment

Excel-only upload, 5 MB cap, header validation, per-row consent, and a created / updated / skipped report.

POST /cadets/bulk-uploadGET /cadets/template

Parade

Lock & override

The environment sets the 24-hour window. A locked save by an officer is audited as an override; a leader is blocked.

ATTENDANCE_LOCK_HOURS=24attendance.override

Export

Column whitelist

Three formats, a server-side whitelist, sensitive-column role check, row cap detection and per-download audit metadata.

GET /cadets/export.*parseColumns()

Gap

Write surfaces

News composer, account provisioning, audit viewer and user lifecycle are not screens in the running app.
