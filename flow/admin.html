02 / What they can do

Own the system.
Not the day-to-day.

The admin is a super-set of the officer: every operational route is available, plus access provisioning, deactivation and governance. Day-to-day running is delegated.

01

Own the register

Browse every active cadet, edit any record, and see all personal fields including parent contact and address.

Live MVP
02

Provision access

Create accounts with a role and optional register number, then link the login to the matching cadet record.

Api-ready UI
03

Deactivate, never erase

Soft-delete an exited cadet. All attendance and history remain available for audits and past reports.

Live MVP
04

Operate as officer

Enrol by bulk upload, open parades, override attendance locks, publish notices and download the full export.

Live MVP
05

Review audit evidence

Audit rows are written for every edit, export and override, but there is no read API or UI yet.

Data-only
06

Roll the academic year

Promote years, exit a batch and keep historical platoon lists queryable. Currently a documented script slot.

Phase 2

Can authority

  • See and export every cadet column, including contact PII.
  • Create any role, including another super admin.
  • Deactivate a cadet without destroying attendance history.
  • Override a locked parade (officer power, audited).
  • Share the full wing dashboard and reporting surface with officers.
  • Revoke its own refresh sessions across devices.

Cannot guardrails

  • Read the audit trail through the API yet — no endpoint exists.
  • Hard-delete a cadet or wipe attendance records.
  • Make an edit or export without writing an audit row.
  • Reset a password or deactivate a user login — no endpoint yet.
  • Run an automatic year rollover; it is still a Phase 2 script.

04 / Evidence & gaps

What is built,
what is not.

This is the honest line between the running MVP and the governance UI being proposed. Use it to frame the next sprint, not to hide a gap.

Access

Registration

Token-gated staff onboarding, self-service cadet signup only when the environment explicitly opts in.

POST /auth/registerrequireOfficer

Lifecycle

Soft deactivation

The only delete is a soft deactivate; records remain queryable by history and exports.

DELETE /cadets/:idSUPER_ADMIN only

Oversight

Audit writes

Every export, override, edit and sign-in event lands in a dedicated audit table with IP and metadata.

AuditLogaudit() helper

Wing view

Dashboard

The admin shares the staff summary: strength, average, low-attendance count, department split, upcoming camps.

GET /dashboard/summary

Exports

Full reporting

Excel, CSV and print-ready PDF, with column whitelist, row cap and per-download audit metadata.

GET /cadets/export.*

Gap

Read-side governance

No audit read API, no user management endpoint and no rollover UI. These are the next admin deliverables.
