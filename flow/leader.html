Platoon Leader

LEADER_SUO · Senior Under Officer · Alpha platoon

Runs one platoon, not the wing. Opens Alpha parades, marks the roster on a phone — offline if the ground has no signal — publishes notices, and reads a scoped register. The server derives the platoon from the leader's linked cadet record, never from the URL.

01 / What they see

A platoon-sized console.

The leader sees a deliberately smaller app: Alpha's readiness, a scoped roster, parade marking and the notice board. There is no wing register, no account screen and no attendance override.

The tabs inside the frame are live. The offline toggle in Parade is a local simulation of the production queue.

02 / What they can do

Lead the platoon.
Leave the wing alone.

A leader is a staff role, not a junior officer. The design gives them enough to run a parade and brief a platoon, while the server refuses every request that would widen the scope.

01

See Alpha, only Alpha

The linked cadet record resolves the platoon. Register, roster, reports and exports all inherit the same scope.

Live MVP
02

Read a safe contact view

Phone and email stay for platoon administration. Parent contact and address are stripped server-side before the response leaves.

Live MVP
03

Mark an Alpha parade

Open a platoon session, mark exceptions, or set everyone present. The roster is rebuilt server-side from the session.

Live MVP
04

Survive the parade ground

Weak-network saves queue on the device and retry when the browser comes back online. The queue is visible, not silent.

Live MVP
05

Read the platoon report

Download attendance totals for Alpha. Wing-wide sessions are included so the report is complete, but only Alpha cadets appear.

Live MVP
06

Publish a notice

Create a wing-wide notice with a priority. Editing and withdrawal remain officer-only; the leader UI omits both controls.

Live MVP

Can authority

  • Read the Alpha roster with phone and email.
  • Open and mark an Alpha platoon session.
  • Queue marks offline and sync them on reconnect.
  • See Alpha's slice of wing-wide sessions in the attendance report.
  • Export an Alpha register without sensitive columns.
  • Publish an announcement to the wing-wide public board.
  • See the cached attendance percentage and low-attendance flag.

Cannot guardrails

  • Read another platoon or the whole wing — a hand-edited filter returns 403.
  • Mark a wing-wide session; the API explicitly rejects it.
  • Amend a session after the 24-hour lock — only an officer can override.
  • See parent contact or address, even in an export.
  • Request phone, email or parent contact in an export — 403.
  • Edit or withdraw an announcement, create a cadet, or bulk-upload.
  • Deactivate a cadet, manage accounts or read the audit trail.

03 / Role journey

Resolve scope.
Mark. Hand off.

The leader's loop is short and physical: get the scope, check the roster, mark the parade, deal with the network, publish what the platoon needs to know.

04 / Evidence & gaps

A narrow role,
enforced in code.

The important part of this perspective is what is absent. Every omission below is a server rule, not a missing button that a clever user could route around.

Scope

Linked record

Scope is derived from the cadet record linked to the login. An unlinked leader gets a 403, not an empty platoon.

staffScope()common/scope.ts

PII

Role-shaped DTO

Leaders lose parent contact and address. Officers get the full DTO. The cadet's own record is the separate /me path.

stripPII()LEADER_SUO

Parade

No wing-wide marking

Session scope is checked before the roster is built. A leader cannot mark a session with no platoon.

POST /attendance/sessions/:id/mark

Lock

No override path

After the lock window, a leader receives 403. The officer exception is the only amendment route.

ATTENDANCE_LOCK_HOURS=24

Board

Publish-only

Create is staff-only; update and delete require an officer. There is no platoon audience field.

POST /announcementsPATCH/DELETE → requireOfficer

Gap

No duty roster

Duty allocation, camp nomination and junior-rank management are not in the current schema or UI.

Team-lead note

The leader can publish a wing-wide notice. That is a deliberate staff role, but it surprises people. The interface says so before the form and the guide repeats it. If platoon-only notices are required, that is a schema change, not a filter.
